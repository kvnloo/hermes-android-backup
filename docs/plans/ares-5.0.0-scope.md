# 5.0.0 parity acceptance checklist

Source baseline: Ares 4.0.15 and Hermes Desktop 0.23.4. Entries describe the audit baseline, not claims about this build. `OPEN` stays open until the workflow is implemented and verified. Linux packaging and a native Windows notification proof are explicit acceptance gates. Host operations mean *operate the authenticated remote gateway*, not host Hermes in Ares. The remote Webapp row grants no exception to the no-local-hosting rule.

### F23 notes (v5/render, Desktop b7ee21c14e)

- **Setup and install cards.** `setup_beat` is the onboarding server request (`tui_gateway/contracts/server_requests.py`); both layouts draw its card above the composer and answer it on the request's own socket for the owning chat only (`lib/core/render/setup_beat.dart`). There is no `catalog_install` tool: the Desktop's catalog-install card is `manage_catalog`'s connection operation (`connection.request` / `connection.update` / `connection.respond`, `tui_gateway/contracts/connectors_operation.py`); both layouts draw it (`lib/core/render/catalog_install.dart`) and retry a settled failed plugin through `plugins.manage` with its catalog name and target profile. Ares draws both above the composer rather than inside the tool row, because tool rows are hidden when Verbose Mode is off.
- **Transcript video.** Ares's transcript video is the player a delivered video card opens. Speed and seek drive the player, and the position and speed are remembered per source for the chat and connection (`lib/core/render/video_playback_memory.dart`), as `transcript-video.tsx` remembers them per source.
- **Preview suggestions: not shipped.** The Desktop equivalent is the composer status stack's dismissible preview rows (`apps/desktop/src/app/chat/composer/status-stack/index.tsx`, `PreviewStatusRow`), fed by tool preview outcomes (`gateway-event/tools.ts`, `toolPreviewOutcome`) and preview links in replies (`markdown-text.tsx`, `previewTargetFromMarkdownHref`). They open the right-rail preview pane, and a `localhost` row is kept only while a dev server runs in that session. Ares's reader preview fetches on the device itself (`lib/core/preview/reader_document.dart`), so a `localhost` address on the gateway host cannot be opened from a phone until F02's managed tunnel exists; a chip would point at the phone. Delivered files already open as media cards and `::preview` widgets. No preview chip ships until the tunnel and a per-session dev-server signal exist.
- **Embeds.** Ares embeds no third-party player (no WebView), so YouTube, TikTok and Maps links stay ordinary links; the consent card was removed.

Evidence detail: [Desktop guide](https://hermes-agent.nousresearch.com/docs/user-guide/desktop); [pinned Desktop](https://github.com/NousResearch/hermes-agent/tree/b7ee21c14e38316273f88d8ed112491ba1c87d15/apps/desktop); [pinned Ares](https://github.com/rusty4444/ares/tree/66fb4452192e5900e4e5342246aebe49b636d017/lib).

## Release decisions (Sam, 26 November 2026)

- **SSH trust:** managed SSH bootstrap and adoption use the gateway's trust-on-first-use, as Hermes Desktop does, behind a clear warning. A changed host key is never accepted silently. The strict pinned path (paste a key you obtained yourself) stays available as the stronger option.
- **LGPL in voice:** the Windows and Linux WebRTC libraries bundled for GPT-Live include FFmpeg under LGPL-2.1-or-later, dynamically linked. Accepted as documented in `third_party/webrtc/NOTICE.md`.
- **Hands-on verification:** Sam tests the Windows build (notification banner clicks warm and cold, the MSIX pop-out, tray, close-to-tray and the global hotkey) and the Android build (GPT-Live and the microphone, lifecycle around permission prompts) on his own devices. Linux lock/resume on GNOME, KDE and sway and the macOS permission flows are recorded as untested on hardware unless Sam runs them.
- **No in-app updater:** the in-app GitHub update check and APK installer were removed from every platform in 4.0.18 (PR #379). 5.0 takes that removal too, along with the rest of 4.0.16 to 4.0.18. Updates come from the stores or the GitHub releases page.
