# Ares 4.0.12

Stable release `4.0.12+3068`. ABI split codes `30681` (armeabi-v7a),
`30682` (arm64-v8a) and `30683` (x86_64), each above the highest published
4.0.11 split (`30673`). The production package `com.hermesagent.hermes_android`
and signing certificate are unchanged; install over the existing app.

## Added

### A Models page in NextGen (#347)

NextGen's model settings are now one page. Open it from **Settings → Model
management**, **More → Model management** or the top of a chat's model picker.

- **Default model.** The model and provider, then what the gateway reports
  about it: context window (and the auto-detected size when the gateway
  overrides it), maximum output, input, output and cached-input prices, and
  whether it supports tools, vision, reasoning and fast mode. **Change** opens a
  searchable list of every model that can be assigned, with its price.
- **Fallback models.** The ordered list with each entry's provider and price.
  Entries are added, moved and removed; nothing is sent until **Save fallback
  list**, and unsaved edits survive a refresh.
- **Auxiliary models.** Each helper task by name with a line on what it does
  and the model it uses. Tapping a task chooses a model, returns it to the
  default model, or sets its thinking level where the gateway reports one.
- **Providers.** Every provider the gateway lists, how many models it has,
  which one is in use, subscription allowance per window and any rate limit
  with its reset time.

A change counts as saved only after it has been read back from the gateway, and
one change runs at a time. When the gateway warns that a model is expensive, the
page shows the gateway's warning and assigns the model only if you agree.
Anything the gateway does not report is left out rather than guessed. Models on
a custom endpoint are listed but cannot be reassigned from the app, and no
endpoint address, credential or key name is shown. The classic model screen is
unchanged. Details: [model management](../model-management.md).

## Install

Download the APK for your device from the release assets and install over the
existing app; do not uninstall or clear app data. The Google Play build
updates through Play.

## Verification

- `flutter analyze --no-pub --fatal-infos`: no issues.
- #347's CI (Analyze & Test, Android native regressions, Push companion and
  Dart TCP contract) passed at its exact merged head.
- One code review of the feature commit found no blocking defect; its four
  findings were fixed with regression tests before the merge.
- The page's own data layer was run over loopback against the installed Hermes
  Agent's real model and config routes with a disposable home: loads, helper
  model and thinking-level changes, the confirmation step, fallback list saves
  including an entry with routing details, an unknown profile, and an untouched
  launch profile. That run was offline and without sign-in, so prices,
  allowances and the default-model validation were covered by tests only.
- Not run on a phone before release.
- Release APKs are production-signed and verified against the established
  certificate, package, ABI and version-code gates by the release workflow.
