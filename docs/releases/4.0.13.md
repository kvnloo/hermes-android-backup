# Ares 4.0.13

Stable release `4.0.13+3069`. ABI split codes `30691` (armeabi-v7a),
`30692` (arm64-v8a) and `30693` (x86_64), each above the highest published
4.0.12 split (`30683`). The production package `com.hermesagent.hermes_android`
and signing certificate are unchanged; install over the existing app.

## Fixed

### The Models page can change the default and fallback models (#357)

In 4.0.12 the NextGen Models page made the default model read-only whenever
its provider had an address saved with it that the app did not recognise. That
covered every provider plugin and every named endpoint, so on many setups the
default could not be changed at all. Named endpoints could not be chosen for
anything, and a fallback row could be added, moved or removed but not given
another model.

- **Any provider the gateway lists by name** can be chosen as the default, a
  fallback or a helper-task model, named endpoints (`providers:` entries)
  included. The app sends only the provider and model; the gateway applies
  that provider's address and key.
- **Tapping a fallback row** gives it another model. Rows with routing details
  (an address or key of their own) keep their model and can still be moved or
  removed.
- **The default stays read-only** only when its address would not come back on
  choosing its provider again: an endpoint with no name (`custom`, `local` and
  local-server names such as `ollama`), a named endpoint used at another
  address, or an address typed for a provider the app has no reviewed address
  for. A provider plugin's own `process://` address, a named endpoint at its
  own address and a provider's standard address are all fine.
- Endpoints with no name and the `custom:` rows made up for legacy entries are
  shown but not offered.

The classic model screen is unchanged. Details:
[model management](../model-management.md).

## Install

Download the APK for your device from the release assets and install over the
existing app; do not uninstall or clear app data. The Google Play build
updates through Play.

## Verification

- `flutter analyze --no-pub --fatal-infos`: no issues.
- #357's CI (Analyze & Test, Android native regressions, Push companion and
  Dart TCP contract) passed at its exact merged head.
- The gateway side was run against the installed Hermes Agent's real model and
  config routes over disposable homes with the network refused: default-model
  switches between named endpoints, to and from a standard provider and to
  legacy entries, refused unknown models, helper tasks and fallback lists on
  named endpoints, and each fallback row resolving to its own address and key.
  The standard-provider validation needs that provider's network, so that step
  used a test seam.
- One code review found a blocking case (local-server names and a capitalised
  `Custom` would have become changeable); it was fixed with tests before the
  merge.
- Not run on a phone before release.
- Release APKs are production-signed and verified against the established
  certificate, package, ABI and version-code gates by the release workflow.
